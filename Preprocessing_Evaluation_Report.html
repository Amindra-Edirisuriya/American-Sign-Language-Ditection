Data preprocessing for ASL recognition

The goal was to turn hand landmarks into consistent model inputs and create a fair way to evaluate the classifier. If two captures of the same gesture are nearly identical, putting one in training and the other in testing can make accuracy look better than it would be on fresh captures.

Representing each gesture

The dataset contains 64,376 samples across 28 gesture classes. Each sample describes 21 MediaPipe hand landmarks. The CSV loader orders them by landmark ID, checks that IDs 0 through 20 each appear once, and validates that every X, Y and Z coordinate is a finite number. It flattens the coordinates into 63 features per sample. The folder name supplies the gesture label. The current workflow loads these features and labels from data/landmarks.npz.

Grouping related captures and removing duplicates

We linked samples with identical coordinates. When filename timestamps were available, we also linked adjacent captures of the same gesture class taken at most one second apart. Links form a group: captures at 0.0, 0.8 and 1.6 seconds would stay together because each consecutive pair satisfies the rule. We formed groups before removing duplicates so deleting a row could not break a link.

For each repeated vector with one label, we kept the first sample in a stable filename order within its class. The procedure also checks for identical vectors assigned different labels and excludes all copies if that happens. We found no such conflicts. Removing 657 duplicate rows left 63,719 samples in 34,495 groups.

Creating the training, validation and test sets

We assigned whole groups to sets using shuffled stratified group folds. Stratification aims to preserve the mix of gesture labels. We reserved one of five folds for testing, then one of four remaining-data folds for validation. Fixed random seeds make the split repeatable. Keeping each group intact explains the small difference from the 60/20/20 target. All 28 classes appear in each set.

Checks before model training

The audit found zero exact coordinate vectors shared between sets. It checked 29,224 same-class timestamp links and found zero crossing a set boundary. The training script verifies the saved dataset and split fingerprint and repeats the overlap checks before fitting. Its pipeline learns each feature’s mean and scale from training samples alone and applies those values to validation and test samples.

Limitation. Timestamps were unavailable for 34,896 retained samples. The dataset also lacks signer and session IDs. The audit therefore establishes separation for the links we could check. Performance on entirely new signers remains an open question.

One-minute presentation

“My contribution was preparing the hand landmark data for model training. Each gesture has 21 landmarks, and each landmark has three coordinates, giving us 63 features per sample. The main challenge was keeping closely related captures together. For example, two captures of the same sign taken half a second apart might look almost identical. We grouped those captures when timestamps were available and kept each group in one set. We also removed 657 exact duplicates, leaving 63,719 samples. We split them roughly 60 percent for training, 20 percent for validation and 20 percent for testing. Our audit found zero exact duplicates shared across sets. One limitation is that we had no signer IDs, so we couldn’t verify how well the model generalizes to entirely new people.”
